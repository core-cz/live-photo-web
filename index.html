下载

iPhone / iPad .zip 下载后到「文件」App 解压 → 同时勾选 JPG 和 MOV → 分享 →「存储到照片」 Android .MP.jpg 下载后移进 DCIM 或 Pictures 目录，相册里长按照片即可播放 两个都要 .zip 两套文件 + .livp 备份 + 导入说明

iOS 与 Android 是两套互不兼容的容器，同一个文件无法被两端同时识别，所以给两份。iPhone 务必用第一张卡片：iOS 只认「文件」App 里同时选中同名 JPG + MOV 再存储到照片，单独的 .livp 是导不进去的。

它是怎么工作的

  1. 拖进来如果本身已经是实况照片（JPEG 文件尾挂着 MP4），会把它内嵌的那段视频原样直通——不重编码、不丢音轨、不截时长。其它素材才走转码。
  2. 在浏览器里用 ffmpeg.wasm 裁片段，封面帧默认落在第 1.5 秒（可用滑块调）；静态图会补一条静音 AAC，保证和剪映一样是 video+audio 双轨。
  3. 用 canvas 抓取封面，写入 Apple MakerNote 的 0x0011 与 QuickTime 的 content.identifier，两边共用同一个 UUID。
  4. 把一条真实 Live Photo 的 still-image-time 元数据轨移植进新视频，与封面一起打包成 ZIP。
  5. Android 侧的结构是从剪映真实产物逐字节比对出来的：Exif → XMP → JFIF → ICC → MPF 的段序、单条目 MPF、以及视频紧贴主图 EOI，一个字节都不能差。EXIF 里干脆不写 Make／Model——写了 Apple 会让相册去找同名 MOV，写了 Google 会让微信把实况开关默认打开却播不出来。
  6. 视频容器里还写回了一段 OPPO 私有元数据（moov → udta → meta → LvMetaInfo / Hw / te_is_reencode）。ffmpeg 重封装会把它换成 33 字节的空壳，微信正是靠这段判断「是不是原厂导出的实况」——少了不掉画质，是直接掉图标。
  7. 视频短边压到 480（剪映的实况就是 480×852）。超过这个尺寸 ColorOS 会提示「规格较高」并切到降级播放，画面能动但没声音；封面则保持 720 短边、比例与视频严格一致。

所有处理都在你的设备上完成，文件不会上传到任何服务器。首次使用需下载约 10MB 编码器。
